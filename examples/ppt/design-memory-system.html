MEMORY EVOLUTION
04 / 12
BEFORE vs AFTER

记忆系统演进

BEFORE 旧方案
MEMORY.md
纯文本 Markdown 文件，按分类存储用户偏好和项目约束。
  • 人类可读，但不可搜索
  • 无去重机制，靠 LLM 判断
  • 无法按类型/概念过滤
  • 无统计和晋升能力
AFTER 新方案
Observation + 混合检索
SQLite 结构化存储 + FTS5 全文检索 + ChromaDB 向量检索。
  • 结构化数据，支持多维过滤
  • content_hash 去重，ON CONFLICT DO NOTHING
  • FTS5 关键词 + 向量语义双路检索
  • relevance_count 驱动自动晋升

DATA MODEL

Observation 结构

01
type
bugfix / feature / refactor / change / discovery / decision
02
title + narrative
一句话标题 + 1-3 段详细描述，构成记忆主体

关键事实列表 + 概念标签，支撑搜索过滤

files_read / modified
涉及的文件路径，支持按文件回溯记忆
05
content_hash
SHA-256 去重哈希，UNIQUE 约束防重复插入
06
relevance_count
被检索引用次数，达到阈值自动晋升到 MEMORY.md

PROMOTION
08 / 12
RELEVANCE-DRIVEN PROMOTION

晋升机制

01 追踪
引用计数
每次检索命中 observation 时，relevance_count += 1。高频引用 = 高价值记忆。
  • 检索命中自动触发
  • 阈值可配置（默认 3 次）
  • 已晋升的不再重复晋升
02 晋升
写入 MEMORY.md
LLM 将 observation 压缩为一句话，追加到 MEMORY.md 对应分类。
  • bugfix / decision → 项目约束
  • feature / discovery → 历史上下文
  • 标记 promoted 状态，跳过后续晋升
